GLOBAL CONVENTIONS — paste once, applies to every stage below
----------------------------------------------------------------
Stack: Create React App (CRA) — not Vite. Do not assume Vite-specific
conventions (import.meta.glob, vite.config.js, ESM-only imports).

- Status/category fields are stable codes, never display text. An
  application's status is a code (FULFILLED, WITHDRAWN, DOC_VERIFICATION,
  etc.) with the human-readable label as a separate lookup. Filtering,
  comparison, and storage always use the code.
- Canonical vs. display data. A customer's name and any system-generated ID
  (application ID, document ID, correlation ID) have one canonical value
  each — used as-is everywhere (bureau checks, audit trails, cross-system
  correlation). Never translated, localized, or transliterated for display,
  regardless of UI language.
- Search matches canonical fields, never a translated or formatted display
  string.
- Per-story organization. The frontend is organized by user story/feature,
  not technical layer — each story owns its own pages and components in an
  isolated folder. Cross-story reuse goes in shared/components/, not into
  another story's folder.
- Closed color palette. Fixed, approved set (brand navy, blue, green,
  grays, semantic error/warning). No new colors without a design decision.
- No i18n yet, but keep the status-code/display-label separation in place
  so it doesn't need a rearchitecture later.

DECISIONS LOCKED IN THIS ROUND (full list — know these even if your stage
doesn't touch them directly, since adjacent stages depend on them):
1. Editing is removed entirely. No application, once submitted, can be
   edited — not from the dashboard, not from View Application, nowhere.
2. Delete is removed. Terminate replaces it. Terminate requires Password +
   Comment/Reason, halts all in-flight processes, sets status to WITHDRAWN.
3. Document status is inline only — no pop-ups or modals, anywhere.
4. Document preview is a dedicated page, not inline rendering. Clicking
   "Preview" navigates to a full page showing all documents for that
   application together, each individually downloadable.
5. Download is per-document only. No bulk/zip export of documents (the
   dashboard's "Select All" bulk-download is for application *records*,
   a separate feature — keep the two distinct).
6. Credit Decisioning: white-space instruction dropped. Do not populate the
   empty screen area with "Offer Details."
7. Credit Decisioning: escalation requires a comment before it sends.
8. Row action menus replace standalone Actions columns everywhere, via a
   3-dot menu with a configurable option list:
     - Application lists (dashboard, View Application): View, Terminate.
     - Credit Decisioning queue: Review, Send To Manager for Review/Approval.
